# 勤怠タイムカード（Node.js + SQLite）

日本企業向けの勤怠サイトです。外部パッケージは使わず、Node.js 標準の `node:http` と `node:sqlite` だけで動きます。`npm install` は不要です。

## 必要なもの

- Node.js 22.13 以上（`node -v` で確認）

## 起動

```bash
# 最初の管理者を作って起動（ユーザーが1人もいないときだけ作成されます）
ADMIN_EMAIL=admin@example.co.jp ADMIN_PASSWORD='8文字以上のパスワード' node server.js
```

ブラウザで http://127.0.0.1:3000 を開き、メールアドレスとパスワードでログインします。2回目以降は環境変数なしで `node server.js` だけで起動できます。

## ログインと社員の追加

- 社員は全員、自分のメールアドレスとパスワードでログインします。メールアドレスの大文字と小文字は区別しません。
- 管理者が「管理者メニュー」から社員を追加します。メールアドレス、氏名、仮パスワードを入力し、社員番号は任意です。
- 管理者は仮パスワードを本人に伝えます。本人は初回ログイン時に、自分のパスワードへ変更しないと打刻などを使えません。
- パスワードを忘れたときは、管理者が「仮パスワードで再設定」を行います。再設定すると本人のログインは終了し、次回ログイン時にもう一度パスワードを変更します。
- このサーバーはメールを送信しません。仮パスワードは管理者が直接（対面、チャットなど）伝えてください。「パスワードを忘れた方」の自動メールが必要な場合は、メール送信（SMTP）の設定が必要になります。

コマンドで追加する場合は次のとおりです。

```bash
npm run create-user -- taro@example.co.jp "山田 太郎"          # 一般社員（初回ログイン時にパスワード変更）
EMP_NO=E-002 npm run create-user -- hanako@example.co.jp "佐藤 花子"   # 社員番号を付ける
npm run create-user -- soumu@example.co.jp "総務 花子" admin   # 管理者
```

> 以前の版（社員番号でログイン）で作ったデータベースは、そのままでは使えません。起動時にエラーで知らせます。テストデータであれば `data/timecard.db` を削除して起動し直してください。

## 設定（環境変数）

| 変数 | 既定値 | 内容 |
| --- | --- | --- |
| `PORT` | 3000 | 待ち受けポート |
| `HOST` | 127.0.0.1 | 待ち受けアドレス。社内ネットワークに公開するときは `0.0.0.0` |
| `DB_FILE` | ./data/timecard.db | SQLiteのファイルの場所 |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` / `ADMIN_NAME` | （なし） | 最初の管理者を作るときだけ使います |
| `COOKIE_SECURE` | （なし） | HTTPSで公開するときは `1`。ログインCookieにSecureが付きます |
| `TRUST_PROXY` | （なし） | リバースプロキシ配下では `1`。`X-Forwarded-For` をログイン試行の制限に使います |

## 構成

```
server.js            サーバー本体（API、認証、CSV、静的ファイル配信）
db.js                SQLiteのスキーマとパスワードのハッシュ化
scripts/create-user.js  コマンドから社員を追加（メールアドレスで指定）
public/index.html    画面（ログイン、打刻、月次表）。管理メニューは含みません
admin/ui.js          管理メニューの画面とプログラム（管理者にだけ配信。公開フォルダには置かない）
public/style.css     デザイン
public/pages.js      追加機能の画面（振替・交通費・立替・現場情報・キャリアシート）
public/menu.js       ☰ メニュー
features.js          追加機能のAPIとテーブル、Excel出力の内容
xlsx.js              Excel（.xlsx）ファイルの生成
public/app.js        画面の動き（APIを呼び出す）
public/calc.js       勤務時間の計算（ブラウザとサーバーで共通）
data/timecard.db     起動すると自動で作成されるデータベース
```


## メニューと追加機能

ログイン後、右上の「☰ メニュー」から開きます。

| メニュー | 内容 | 承認 |
| --- | --- | --- |
| 勤怠登録 / 勤怠修正 | 打刻と月次表（これまでの画面） | - |
| 振替管理 | 休日出勤日と振替休日の申請 | 管理者が承認・差し戻し |
| 交通費(現場請求用) | 現場ごとの交通費。現場は「現場情報」から選ぶ | 管理者が承認・差し戻し |
| 交通費(社内向け) | 社内の移動の交通費（目的を入力） | 管理者が承認・差し戻し |
| 立替申請 | 立替払いの申請（分類・内容・支払先・金額） | 管理者が承認・差し戻し |
| 現場情報 | 現場の一覧と検索。追加・修正・削除は管理者だけ | - |
| キャリアデザインシート | 職種、職務内容、資格、技能・スキル（レベル1〜5）、職務経歴、今後の希望 | - |
| フォーマット印刷 | ブラウザの印刷画面を開く | - |

- 申請は「承認待ち」で登録され、承認待ちの間は本人が修正・削除できます。承認または差し戻しの後は修正できません。
- 管理者は「全員を表示」で全社員の申請を見て、承認・差し戻しができます。社員は自分の申請だけ見えます。
- キャリアデザインシートは本人だけが編集できます。管理者は社員を選んで閲覧とExcel出力ができます。
- 現場を削除しても、過去の交通費の記録は残ります（一覧から非表示になるだけです）。

## Excel出力

- 勤怠表、振替、交通費、立替、現場情報、キャリアシートの各画面に「Excelを保存」ボタンがあります（.xlsx。外部パッケージなしで生成）。
- 見出しの色、罫線、列幅、土日祝の色分け、先頭行の固定、フィルター、印刷設定（A4横・1ページ幅）が付きます。
- 交通費と立替の合計は Excel の数式（差し戻しを除く）なので、Excel上で行を編集すると合計も変わります。
- 保存するとき（勤怠の修正、各申請、現場、キャリアシート）に Excel も自動で保存されます。メニュー下部の「保存するとき、Excelも自動で保存する」で切り替えます（ブラウザごとに記憶）。
- 管理者は、勤怠一覧（全社員の月次集計）と、社員ごとの勤怠表を Excel で出力できます（`/api/admin/export.xlsx?month=2026-11`、社員は `&user=ID`）。

## データベース

- `users` 社員（メールアドレス、社員番号（任意）、氏名、パスワードのハッシュ、権限、勤務設定）
- `days` 日ごとの勤怠（出勤、退勤、休憩、区分、備考）。主キーは社員と日付
- `sessions` ログインの状態（トークンはハッシュで保存、有効期間7日）
- `audit_log` 打刻と修正の履歴（誰が、いつ、変更前と変更後）
- `records` 振替・交通費・立替の申請（種類、日付、入力内容JSON、承認状態）
- `sites` 現場情報
- `career` キャリアデザインシート（社員ごとに1件）

バックアップは `data/timecard.db`（と、あれば `-wal`、`-shm`）をコピーするか、停止中に `.db` ファイルをコピーしてください。

## 管理メニューの表示

管理メニュー（全社員の集計、社員の追加、パスワードの再設定、社員の無効化）は、管理者だけに表示されます。

- 一般社員がログインしても、管理メニューの画面もプログラムも、ブラウザに送られません。画面を隠しているのではなく、そもそも届きません。
- 管理者がログインしたときだけ、サーバーが `admin/ui.js` を配信し、画面に管理メニューが加わります。
- 一般社員が管理用の機能を直接呼び出しても、サーバーが拒否します（403）。
- ログアウトすると、管理メニューは画面から消えます。

## 計算のルール

- 打刻の時刻は、端末ではなくサーバーの時刻（日本時間）で記録します。
- 残業は、所定労働時間（初期値8時間）を超えた分です。
- 深夜は、22時から翌5時までの勤務です。
- 休憩を打刻しなかった日は、6時間を超える勤務に所定休憩（初期値60分）を差し引きます。
- 祝日は `public/calc.js` の `HOL` に2026年と2027年を入れています。以降の年は毎年追記してください。

## セキュリティ

- パスワードは scrypt でハッシュ化して保存します。
- ログインCookieは HttpOnly、SameSite=Lax です。
- 他サイトからの書き込みは Origin を見て拒否します。
- ログインを10分間に10回失敗すると、そのIPからの試行を一時的に止めます。メールアドレスの有無で応答や処理時間が変わらないようにしています。
- パスワードを変更すると、他の端末のログインは終了します。
- SQLはすべてプレースホルダ（?）を使っています。
- 公開するときは、必ず HTTPS のリバースプロキシ（nginx など）の後ろに置き、`COOKIE_SECURE=1` と `TRUST_PROXY=1` を設定してください。

## できないこと・今後の拡張

- 無効にした社員を画面から戻す操作はありません（DBで `UPDATE users SET active = 1 WHERE email = '...'`）。
- 社員のメールアドレスの変更（異動や改姓など）は画面からできません（DBで `UPDATE users SET email = '新しいアドレス' WHERE email = '古いアドレス'`）。メールアドレスの持ち主の確認（認証メール）も行いません。
- 管理者が他の社員の勤怠を直接修正する機能はありません。閲覧とCSV出力のみです。
- 承認フロー、36協定の残業上限の警告、給与システムとの連携は含まれていません。

node server.js
http://127.0.0.1:3000
